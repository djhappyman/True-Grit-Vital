## Product and UI rules

Use shadcn_flutter, Riverpod, Drift/SQLite and go_router. Preserve current package pins and encryption/record integrity. Add no dependencies. Use pure-white light canvas, green-black/mint dark tokens, fixed bottom navigation, device/keyboard safe areas and 48px minimum targets. Cards grow for long names/units and large text; preserve source identity and exact quantities. Central containers/components are reused, with opaque fallback and reduced effects; do not enable the glass gate.

App text follows `docs/specification/content-and-interaction.md`: localisable complete messages with placeholder metadata, authored headings of 1–3 words, one-word visible action buttons, concise positive toggle labels and right-aligned English switches. Existing shadcn controls stay. Distinguish loading, empty, filtered-empty, partial, unknown and failure with recovery. No fabricated clinical, cryptographic, completion or notification claims.

Preserve existing taken/skip/snooze/extra/edit/Undo guards, strength/source selection, duplicate/stale protection and private draft/lock behaviour. Schedules are expectations, not proof of actual use. Time groups use the expectation's real timezone/window; unresolved timezone or bounded calculation is visibly incomplete. Skips are resolved decisions, not taken doses. Zero planned doses is not 100% adherence. Stock balances retain exact units and unknown/deficit states; PRN does not imply a run-out date.

Primary documentation checked at dispatch: Flutter accessibility (`https://docs.flutter.dev/ui/accessibility`), Riverpod disposal (`https://riverpod.dev/docs/concepts2/auto_dispose`), Drift streams (`https://drift.simonbinder.eu/dart_api/streams/`). Verify APIs against the pinned packages before applying examples; generic skill snippets are not API contracts.
