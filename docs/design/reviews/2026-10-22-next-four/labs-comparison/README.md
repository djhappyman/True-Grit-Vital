# Lab prior comparison

## Scope

D18's remaining gap was the panel detail's 50-record prior window. A viewed result now uses a complete store-backed earlier comparison instead of one bounded page of unrelated panels.

`lib/data/supporting_comparison_store.dart` adds `supportingEarlierComparisonFor` and its live watch. The query:

- anchors on the viewed panel's collection date and revision, never today or the latest panel;
- reads only current non-voided revisions and excludes the viewed record;
- filters in SQL by exact metric, unit, record kind and effective laboratory, method and specimen identity;
- excludes censored, qualitative and missing candidates when the viewed value has another value kind;
- selects only the newest qualifying comparison day, so it cannot load the marker's lifetime into a provider or widget;
- passes those candidates to the existing `supportingEarlierComparison`, which keeps the established same-day ambiguity, newest-point, current-revision and exact-change rules.

A same-day exact instant remains comparable only when it is strictly earlier. A day-only date on an exact candidate day, or an exact/day-only pair on the same earlier day, stays incomplete rather than inventing a clock.

## UI and copy

`ScreenPanelComparison` watches one result-level stream. Corrections, voids, restores and saves refresh it live; lock hides the panel and a replaced dataset rebuilds through the store provider. The row still shows in-place loading, Retry on failure, found value/date/change, no earlier result and incompatible date/value states. Found and empty results disclose complete coverage with `featurePanelCoverage`. No clinical interpretation was added.

New localisable strings are under the `featurePanel` prefix:

- `featurePanelNoEarlier`
- `featurePanelCoverage`

## Limits

- Host tests and synthetic captures only. Physical-device accessibility, measured performance and Android build evidence remain open.
- Completeness is across all current saved revisions, not superseded revisions. Voided records remain excluded.
- The query loads only the newest comparable day, but a dataset with many panels on that one day will load each matching record for that day. That is required to decide same-day ambiguity and is not a fixed page cap.
- Superseded revisions remain available in the audit view; they are not comparison candidates by design.
