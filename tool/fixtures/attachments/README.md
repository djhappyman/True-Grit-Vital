# Attachment fixture tool

Deterministic synthetic files for ticket 16 protected attachment tests. Python
standard library only. Generation and validation are separate programs.

These fixtures test file handling. They do not prove that a decoder, PDF
renderer, picker or platform adapter accepts or rejects anything. A valid PNG
or PDF here means only that the bytes have the declared structure.

## Commands

Generate into an explicit directory:

```sh
mkdir -p /tmp/vital-attachments
python3 tool/fixtures/attachments/generate.py \
  --output /tmp/vital-attachments/set

python3 tool/fixtures/attachments/validate.py \
  --input /tmp/vital-attachments/set
```

Generate custom stream sizes, for example one 100 MB stream for a workload
test. It is above the default input limit, so it is not an accepted attachment:

```sh
python3 tool/fixtures/attachments/generate.py \
  --output /tmp/vital-attachments/workload \
  --sizes 104857600
```

Run the complete self-test in a temporary directory:

```sh
python3 tool/fixtures/attachments/selftest.py
```

Use `--json` on generation or validation for a machine-readable report.

## Output contract

`manifest.json` records the fixture contract, synthetic provenance, every file
name, size, SHA-256, media classification, declared dimensions or page count and
the boundary label. It contains no timestamps, absolute paths or host details.
The same command produces byte-identical output on the same generator version.

| Fixture | Purpose |
| --- | --- |
| `image-valid-8x8.png` | Small known valid RGBA PNG. |
| `image-valid-as-jpg.jpg` | Valid PNG bytes under a misleading `.jpg` name. |
| `image-text-misleading.png` | Plain text under a `.png` name. |
| `image-truncated.png` | PNG prefix with a partial IDAT and no IEND. |
| `image-malformed-idat.png` | Complete PNG envelope with an invalid zlib stream. |
| `image-decompression-bomb.png` | Tiny PNG whose IHDR declares 65535 x 65535 pixels. |
| `image-at-byte-limit.png` | Valid PNG padded to exactly the input limit. |
| `image-over-byte-limit.png` | Valid PNG padded to one byte over the limit. |
| `pdf-valid-one-page.pdf` | Simple one-page PDF with a valid xref. |
| `pdf-truncated.pdf` | PDF prefix cut before startxref and EOF. |
| `pdf-malformed-xref.pdf` | PDF with EOF and a startxref that points nowhere. |
| `pdf-page-count-bomb.pdf` | Tiny page tree declaring 1,000,000 pages. |
| `empty.bin` | Zero-byte input. |
| `stream-*-byte-limit.bin` | Deterministic opaque streams under, at and over the limit. |
| `stream-size-N-bytes.bin` | Any additional size passed with `--sizes`. |

## Safety

- `--output` is required. The tool refuses the filesystem root, its own source
  directory, any parent of that source and missing parents.
- A non-empty output is replaced only with `--replace` and only when it is a
  complete set generated by this tool with unchanged manifest hashes.
- Unknown, modified, symbolic-link or unexpected entries block replacement and
  remain untouched.
- Files are written through a staging directory inside the output. The manifest
  is moved last.
- Large outputs are streamed. The generator and validator read and write in
  bounded chunks; the self-test records the largest buffer and traced Python
  allocation.
- No network, download, package installation, Flutter command, renderer,
  device, UI or shared application state is used.

## Limits and gaps

The copied contract in `fixture_spec.py` mirrors `lib/domain/attachments.dart`:
16 MiB input, 64 KiB chunks, 16,000,000 pixels, 100 PDF pages, 8 MiB preview and
one frame. Update both together and record why.

Validation checks bytes, hashes, PNG chunk envelopes and CRCs, PDF xref/trailer
structure, content sniffing, boundary sizes and header-only bombs. It does not
decompress the pixel bomb, render a PDF page, decode the image through Flutter
or measure native memory. Renderer and platform acceptance remain tests against
the admitted engine. No G04 result is claimed here.
