# Contributing

For UI work, start with the [interaction blueprint](docs/design/interaction-blueprint.md), then the applicable screen in the [implementation plan](docs/design/interaction-implementation-plan.md). Use the [shared components](docs/design/components.md) and saved design references. Update the blueprint when an agreed rule changes rather than introducing a competing local convention.

Preserve the single-user scope, exact record quantities, durable drafts, revision checks and privacy gates. Include meaningful interaction checks and light/dark captures for changed layouts, including narrow/large text and reduced motion. Run the relevant checks from [README](README.md#verification) before claiming completion. Physical-device and production-release evidence remain separate from host tests.

Commits use an imperative subject, a blank line and changelog-style bullets covering finished changes and relevant verification.
